# Wi-Fi Troubleshooting สำหรับ macOS

แอป SwiftUI อ่านข้อมูลจริงจาก CoreWLAN สำหรับวิเคราะห์ Wi-Fi และสำรวจสัญญาณในพื้นที่ ใช้ macOS 14 ขึ้นไป สร้างด้วย Swift 6 / Command Line Tools บน macOS ไม่ต้องติดตั้งไลบรารีภายนอก

## เปิดใช้งาน

```sh
./scripts/build-app.sh
open 'dist/Wi-Fi Troubleshooting.app'
```

เปิดหน้า **อุปกรณ์และสิทธิ์ → ขอสิทธิ์ตำแหน่ง** เพื่อให้ macOS เปิดเผย SSID/BSSID หากเคยปฏิเสธให้เปิด Location Services ใน System Settings และเปิดแอปใหม่ ควรรันจาก `.app` ไม่ใช่ `swift run` เพื่อให้ระบบระบุแอปที่ขอสิทธิ์ได้

แอปที่ build ในเครื่องใช้ ad-hoc signing; ไม่ได้ notarize สำหรับแจกจ่ายทั่วไป ตั้ง `SIGN_IDENTITY` เป็น signing identity ของคุณเพื่อ build ด้วยใบรับรอง Apple ที่ติดตั้งไว้ การเปลี่ยน signature อาจทำให้ต้องอนุญาต Location ใหม่ ไบนารีที่สร้างเป็นสถาปัตยกรรมของเครื่อง build (ครั้งนี้ arm64)

## รุ่น 1.6 — ป้ายกำกับกราฟเชิงเส้น

กราฟสด จุดสำรวจ และรอบงานย้อนหลังแสดง SSID, primary CH และ MHz ของตัวอย่างล่าสุดหรือจุดที่คลิก/ลากเลือก สีฟ้า = 2.4 GHz, ม่วง = 5 GHz, ส้ม = 6 GHz, เทา = ไม่ทราบย่าน; RSSI เส้นทึบและ Noise เส้นประ พร้อมปุ่มกลับค่าล่าสุด เส้นหยุดเชื่อมเมื่อเปลี่ยน SSID/BSSID/channel/band/interface หรือค่าขาดหาย

ชื่อที่ macOS ไม่เปิดเผยจะแสดง “ไม่เปิดเผย / ไม่ทราบ” ต้องให้สิทธิ์ตำแหน่งเพื่ออ่าน SSID ตามข้อกำหนดของ macOS กราฟเปรียบเทียบก่อน/หลังยังใช้สีแยกรอบ พร้อมรายการ SSID/CH/MHz ใต้กราฟ

## รุ่น 1.5 — ผังช่องสัญญาณแยกย่าน

เปิดเมนู **ผังช่องสัญญาณ** เลือก 2.4 / 5 / 6 GHz แล้วเลือก Primary หรือ Center ตามความกว้างช่อง การ์ดแสดง CH, ความถี่ MHz, จำนวน AP, ช่องที่เชื่อมต่อ และ PSC ใน 6 GHz พร้อมเครื่องหมายช่องที่ CoreWLAN รายงานสำหรับอุปกรณ์/ประเทศปัจจุบัน

- 2.4 GHz: CH 1–14 พร้อมคำอธิบายกรณีพิเศษ CH 14 (legacy 802.11b)
- 5 GHz: กลุ่ม CH 36–64, 100–144 และ 149–177 ขั้นละ 4; center สำหรับ 40/80/160 MHz แยกต่างหาก
- 6 GHz: CH 1, 5, 9 … 233 พร้อม CH 2 = 5935 MHz กรณีพิเศษ; center สำหรับ 40/80/160/320 MHz และป้าย PSC
- ตารางเครือข่ายเพิ่ม MHz และแยก primary/ความกว้างชัดเจน กราฟแยกสามย่านและใช้แกนความถี่จริง พร้อม CH/MHz; ฉาก 3D แสดงป้ายช่องและสเกลความถี่แยกย่าน
- เลือกการ์ดเพื่อดูรายละเอียดและ AP หรือกรองเฉพาะช่องที่ macOS รายงาน การเลือกไม่เปลี่ยนช่องของ router

ผังเป็นข้อมูลอ้างอิง ไม่ใช่การอนุญาตใช้ทุกช่องในทุกประเทศ และรายการ 320 MHz ไม่ใช่การยืนยันความสามารถของเครื่อง ดู [แหล่งอ้างอิงและข้อจำกัด](docs/CHANNEL-REFERENCES.md)

## รุ่น 1.4 — รูปแบบงานและคลังการวัด

หน้าเริ่มต้น **รูปแบบการใช้งาน** มี 4 เส้นทาง: ตรวจปัญหาด่วน, เฝ้าดูและบันทึก, สำรวจพื้นที่ และเปรียบเทียบก่อน–หลัง

### รอบงานและการเปิดย้อนหลัง

1. เปิด **รอบงานและเปรียบเทียบ → บันทึก / ย้อนหลัง** ตั้งชื่อและบันทึกย่อ เช่น ตำแหน่ง ทิศทางเครื่อง และสิ่งที่เปลี่ยน
2. เลือกระยะเวลาสูงสุด 30 วินาที / 1 / 5 / 15 นาที / 1 ชั่วโมง แล้วเริ่มบันทึก ปุ่มนี้เปิด Live ให้อัตโนมัติ
3. หยุดเองหรือรอครบเวลา เก็บสูงสุด 3,600 ตัวอย่างต่อรอบ ไม่ใช้ขีดจำกัด 300 ตัวอย่างของกราฟสด
4. เลือกรอบงานในคลังเพื่อดูกราฟย้อนหลัง เหตุการณ์ล่าสุด และส่งออก JSON ครบชุด หรือ CSV เฉพาะค่าที่วัด
5. อีกทางเลือกคือ **เก็บ snapshot ประวัติสด** เพื่อบันทึก 300 ตัวอย่างล่าสุดทันที

คลังเก็บที่ `~/Library/Application Support/WiFiTroubleshooting/Sessions/<UUID>.json` ไฟล์มีชื่อ/หมายเหตุ เวลาเริ่ม/สิ้นสุด เกณฑ์และรอบอ่านตั้งต้น ตัวอย่างจริง AP snapshot ล่าสุด และเหตุการณ์ระหว่างรอบ (สูงสุด 10,000 รายการ) รองรับนำเข้า JSON โดยสร้างรายการใหม่ ไม่ทับรอบเดิม

ระหว่างบันทึก checkpoint ทุกประมาณ 10 วินาทีที่มีตัวอย่างเข้ามา และบันทึกสุดท้ายเมื่อหยุด/ครบเวลา/ปิดแอปตามปกติ หาก force quit อาจสูญเสียข้อมูลหลัง checkpoint ล่าสุด แต่เปิด checkpoint เดิมดูได้พร้อมสถานะว่ารอบงานไม่สิ้นสุดตามปกติ หาก Live ถูกพัก เวลารอบงานยังนับต่อโดยไม่มีตัวอย่างเพิ่ม

หากบันทึกลงดิสก์ล้มเหลว แอปเก็บรอบงานไว้ในหน่วยความจำเพื่อส่งออก JSON หรือลองบันทึกอีกครั้ง และยกเลิกการปิดแอปตามปกติจนกว่าจะเก็บข้อมูลสำเร็จ การ force quit ยังทำให้ข้อมูลที่ไม่เคยเขียนสูญหายได้

### เปรียบเทียบก่อน–หลัง

เลือกสองรอบที่ต่างกันในแท็บ **เปรียบเทียบก่อน–หลัง** เพื่อดู RSSI เฉลี่ยและผลต่าง สัดส่วนตัวอย่างที่ต่ำกว่าเกณฑ์เดียวกัน และกราฟเทียบวินาทีหลังเริ่มแต่ละรอบ ส่งออกรายงาน TXT ได้

เกณฑ์ร่วมใช้ค่าปัจจุบันในหน้าคุณภาพ ไม่ใช้คนละเกณฑ์ตามไฟล์เดิม แสดงจำนวนตัวอย่าง adapter ย่าน และจำนวน BSSID ที่ทราบประกอบ ควรวัดตำแหน่ง ทิศทางเครื่อง AP และภาระงานให้ใกล้เคียงกัน; ผลต่างไม่ยืนยันสาเหตุ ไม่ใช่ throughput/uptime

รอบงานเก็บถาวรเมื่อเลือกบันทึก ต่างจากประวัติสด/รายการเหตุการณ์ทั่วไปที่อยู่ในหน่วยความจำ ไม่มีการล้างคลังอัตโนมัติ ตรวจพื้นที่ดิสก์ตามปริมาณงานที่เก็บ

## รุ่น 1.3 — วิเคราะห์คุณภาพและเหตุการณ์

- หน้า **คุณภาพและเหตุการณ์**: RSSI เฉลี่ยเลขคณิต (dBm), ต่ำสุด/สูงสุด, ส่วนเบี่ยงเบนมาตรฐาน และสัดส่วนตัวอย่างต่ำกว่าเกณฑ์ ใช้เฉพาะ RSSI ที่อ่านได้จริงใน 300 ตัวอย่างล่าสุด ไม่ใช่ uptime/packet loss
- แจ้งเหตุการณ์ภายในแอปเมื่อ RSSI ต่ำกว่าเกณฑ์ติดต่อกัน 3 ตัวอย่าง และฟื้นตัวเมื่อสูงกว่าเกณฑ์อย่างน้อย 3 dB เพื่อลดการแจ้งซ้ำ
- บันทึกการเปลี่ยน BSSID, band/channel, RSSI หายและกลับมาอ่านได้ เมื่อ BSSID ถูกซ่อนจะไม่เดาว่าเป็น roaming; การเปลี่ยน BSSID อาจเกิดจากเปลี่ยนเครือข่ายด้วย
- พัก Live, เปลี่ยน adapter/เกณฑ์/รอบอ่าน หรือมีช่องว่างการอ่านนานเกินเกณฑ์ จะตั้ง baseline ใหม่เพื่อไม่เชื่อมเหตุการณ์ข้ามช่วงที่ไม่ได้สังเกต
- เก็บ 200 เหตุการณ์ล่าสุดระหว่างเปิดแอป (รวมหลาย adapter พร้อมระบุ interface) และส่งออก CSV ได้ ประวัติ/เหตุการณ์ไม่บันทึกอัตโนมัติลงดิสก์ จึงควรส่งออกก่อนปิดแอป
- จำรอบอ่าน 1/2/5 วินาที รอบสแกน 15/30/60 วินาที สแกนอัตโนมัติ การบันทึกเหตุการณ์ และเกณฑ์สัญญาณอ่อน −90 ถึง −50 dBm ผ่าน UserDefaults
- หน้าเครือข่ายค้นหา SSID/BSSID/Security ได้ จัดเรียงแรง→อ่อน อ่อน→แรง ชื่อ หรือย่าน/ช่องได้ ค่าที่หายอยู่ท้ายผลลัพธ์เสมอเมื่อจัดตาม RSSI
- กรอง RSSI ≥ −75 dBm พร้อมจำนวน AP แยกย่าน และปุ่มส่งออกเฉพาะผลที่กรอง รายละเอียด AP ที่เลือกแสดง Security เต็ม
- หน้าสำรวจเพิ่ม RSSI เฉลี่ยและจำนวนจุดที่ต่ำกว่าเกณฑ์ ไม่ใช่การประเมินพื้นที่ครอบคลุมที่ยังไม่ได้วัด
- ส่งออกประวัติ RSSI/Noise/SNR/rate/SSID/BSSID เป็น CSV ได้จากภาพรวมและหน้าคุณภาพ ข้อมูล SSID/BSSID ยังคงอยู่ในไฟล์ จึงควรตรวจข้อมูลก่อนแบ่งปัน

## รุ่น 1.2 — เลือกกราฟเชิงเส้น / 3D

หน้าภาพรวมและ Signal Space มีปุ่มสลับ **กราฟเชิงเส้น / 3D** จำตัวเลือกเดียวกันทั้งสองหน้าและเมื่อเปิดแอปครั้งถัดไป การสลับไม่ล้างประวัติหรือหยุดการเก็บข้อมูล และไม่รันฉาก 3D ที่ซ่อนไว้เมื่อเลือกกราฟเส้น

กราฟเชิงเส้นแสดง RSSI/Noise ของลิงก์ปัจจุบันตามเวลา ส่วนชุดข้อมูลจุดสำรวจแสดง RSSI ตามลำดับการวัดล่าสุดสูงสุด 300 จุด เส้นเชื่อมไม่ใช่การประมาณความครอบคลุมระหว่างตำแหน่ง มุมมอง 3D ของสัญญาณยังแสดง AP จากการสแกนร่วมด้วย

## รุ่น 1.1 — Signal Studio 3D

- ธีมน้ำเงินเข้ม ตัวเลขเคลื่อนไหวและสีชัดเจน: 2.4 GHz สีฟ้า, 5 GHz สีม่วง, 6 GHz สีส้ม และลิงก์ปัจจุบันสีเขียว
- หน้า **Signal Space 3D** และฉาก 3D ในภาพรวม: ลากเพื่อหมุน เลื่อนเพื่อซูม คลิกแท่งเพื่อดูค่า กดลูกศรย้อนกลับเพื่อคืนมุมกล้อง
- หน้า **สำรวจพื้นที่ → 3D** ใช้ตำแหน่งจุดเดิมบนภาพแผนผังจริงและรักษาอัตราส่วนภาพ ความสูงแท่งแทน RSSI ไม่ใช่ความสูงอาคาร; ปักจุดใหม่ในมุมมอง 2D
- อ่านลิงก์ประมาณทุก 1 วินาที เลือก 1/2/5 วินาที และหยุด Live ได้ สแกน AP อัตโนมัติค่าเริ่มต้นประมาณทุก 30 วินาที (ปรับ 15/30/60 ได้)ด้วย worker แยกจากการอ่านลิงก์
- แสดง LIVE / PAUSED / STALE / WAITING พร้อมอายุข้อมูล STALE เมื่อเกิน 5 วินาทีหรือ 3 เท่าของรอบอ่าน (ใช้ค่าที่มากกว่า)
- การสแกนใช้เวลาและ API/ฮาร์ดแวร์อาจหน่วงได้ จึงไม่ใช่การรับประกันอัตราอ่าน 1 Hz; timestamp จริงเป็นหลัก
- การกระพริบวงแหวนเป็นสถานะการอัปเดต ไม่ใช่การจำลองคลื่นหรือรัศมีครอบคลุม ปิดเมื่อ pause/ข้อมูลเก่า และเคารพ Accessibility Reduce Motion
- SceneKit ตั้งเป้าการวาดที่ 30 fps เมื่อมีภาพเคลื่อนไหว (เฟรมเรตจริงขึ้นกับเครื่อง) ค่านี้ต่างจากอัตราอ่าน Wi-Fi
- ฉาก AP จัดตำแหน่งตาม primary channel ในแต่ละย่าน ไม่ใช่ตำแหน่งทางภูมิศาสตร์; ตัวเลข RSSI และรายละเอียดเวลาเป็นค่าที่วัดจริง
- จำกัดฉาก 3D ที่ 300 AP / 300 จุดล่าสุดเพื่อควบคุมจำนวนวัตถุ ส่วนตาราง/ข้อมูลส่งออกเก็บทั้งหมด
- ใช้ [SceneKit camera controls ของ Apple](https://developer.apple.com/documentation/scenekit/scnview/allowscameracontrol) เพื่อรองรับ macOS 14+; SceneKit ถูกประกาศ deprecated ใน SDK รุ่นใหม่ จึงแยก renderer ไว้ใน `SignalScene.swift` สำหรับการย้ายในอนาคต

## ฟังก์ชัน

- ภาพรวม: RSSI, Noise, SNR, transmit link rate, channel, band, PHY และประวัติสูงสุด 300 ตัวอย่าง อ่านทุกประมาณ 1 วินาที (เลือก 1/2/5 วินาทีได้) หยุดติดตามได้
- เครือข่าย: สแกน AP จริง กรอง SSID/BSSID และย่าน เปรียบเทียบ RSSI ต่อ primary channel ส่งออก CSV สแกนอัตโนมัติประมาณ 30 วินาทีเมื่อเปิดใช้งาน
- สำรวจพื้นที่: นำเข้าแผนผัง PNG/JPEG หรือใช้ตาราง คลิกตำแหน่งเพื่ออ่านสัญญาณจาก Wi-Fi ที่เชื่อมต่อใหม่ ณ เวลานั้น เก็บ SSID, BSSID, RSSI, Noise, band, channel และเวลาในแต่ละจุด ใช้ JSON เปิดต่อภายหลังและ CSV สำหรับวิเคราะห์
- แก้ไขปัญหา: ตรวจ default route, ping gateway 4 ครั้ง, system DNS และ HTTPS ไปยัง www.apple.com พร้อม raw output และส่งออกรายงาน TXT มีทางลัด Wi-Fi Settings และ Wireless Diagnostics
- ข้อมูลและคำอธิบายภาษาไทย ธีมน้ำเงินเข้มพร้อมสีแยกย่านและค่าคุณภาพสัญญาณ

ชื่อโครงการและจุดสำรวจเก็บอัตโนมัติที่ `~/Library/Application Support/WiFiTroubleshooting/survey.json` โครงการปัจจุบันมีหนึ่งรายการ ส่งออก JSON ก่อนเริ่มโครงการใหม่ ไฟล์ JSON รวมภาพแผนผัง ไม่มี telemetry หรือ cloud sync รายการเครือข่ายและประวัติสดอยู่ในหน่วยความจำ

## ย่านความถี่และมาตรฐาน

แยก band จาก `CWChannel.channelBand` โดยตรง รองรับ 2.4, 5, 6 GHz และอ่าน PHY ที่ CoreWLAN รายงานเป็น 802.11a/b/g/n/ac/ax/be (Wi-Fi 4/5/6/6E/7) ทั้งนี้:

- ชิป Wi-Fi, ประเทศ, AP, driver และ macOS ต้องรองรับย่านนั้น ไม่สามารถเพิ่ม 6 GHz ให้ฮาร์ดแวร์ที่ไม่รองรับ
- ax ไม่ได้หมายถึง 6E เสมอไป ต้องตรวจ band 6 GHz ประกอบ
- public API ของ SDK ที่ใช้เปิดเผย width 20/40/80/160 MHz แต่ไม่มีค่าครบสำหรับ 320 MHz, MLO หรือ puncturing แอปไม่เดาข้อมูลเหล่านี้และไม่รับประกันการวิเคราะห์ Wi-Fi 7 ทุกคุณสมบัติ
- ไม่รับประกันว่าจะเห็น AP ทุกตัวหรือเครือข่ายซ่อน ค่า `nil`, RSSI/Noise ที่ไม่สมเหตุผล เช่น 0 แสดงไม่มีข้อมูล
- กราฟ primary channel ไม่ใช่กราฟ spectral occupancy และไม่ใช่ตัววัด channel utilization หรือคลื่นรบกวนที่ไม่ใช่ Wi-Fi
- สีจุดสำรวจแสดงค่าที่วัด ณ จุดจริง ไม่มีการเติมค่าหรือสร้าง heatmap ของบริเวณที่ยังไม่ได้วัด พิกัดเป็นสัดส่วนของภาพ ไม่ใช่พิกัด GPS / ระยะเมตร
- RSSI ≥ −67 dBm ใช้เป็นแนวทางดีทั่วไป, −68 ถึง −75 พอใช้, ต่ำกว่านั้นอ่อน; ไม่ใช่การรับรองคุณภาพงานเสียง/วิดีโอหรือ SLA
- ค่าลิงก์ Mbps ไม่ใช่ internet throughput การตรวจ route/DNS/HTTPS ใช้เส้นทางของระบบ อาจผ่าน Ethernet/VPN และ DNS อาจตอบจาก cache; ping ไม่ตอบไม่ได้ยืนยันว่า gateway เสีย
- แอปแนะนำการแก้ไขและเปิดเครื่องมือระบบ ไม่เปลี่ยน router, DNS, Wi-Fi power หรือการตั้งค่าระบบอัตโนมัติ

## พัฒนาและทดสอบ

```sh
swift build
swift run WiFiCoreChecks
./scripts/build-app.sh
```

`Sources/WiFiCore` เก็บโมเดล validation และ CSV; `Sources/WiFiTroubleshooting` เก็บ SwiftUI, CoreWLAN actor, Location และ diagnostics worker การสแกนและคำสั่งวิเคราะห์ไม่รันบน UI thread คำสั่งภายนอกมี timeout และไม่มี shell interpolation

ชุดตรวจใช้ executable assertions เพื่อรันได้ด้วย Command Line Tools ที่ไม่มี XCTest โดยไม่ต้องติดตั้ง Xcode เต็ม

Tests ครอบคลุมเลข channel ซ้ำข้ามย่าน, ความถี่ 6 GHz channel 2, unknown band, RSSI ที่ใช้ไม่ได้, SNR ที่ขาดข้อมูล, การเปิด/บันทึก survey, version/coordinate validation และ CSV formula injection

### ตรวจด้วยอุปกรณ์จริงก่อนใช้ภาคสนาม

1. เปิด Location Services แล้วสแกน ตรวจ SSID/BSSID กับ Wireless Diagnostics
2. ทดสอบ AP บน 2.4, 5 และ 6 GHz และแต่ละ PHY ด้วยฮาร์ดแวร์ที่รองรับ
3. เดินวัดจุดเดิมหลายครั้ง ตรวจ roaming/BSSID และความแตกต่างเมื่อเปลี่ยนทิศทางเครื่อง
4. นำเข้าแผนผัง ปักจุด เปลี่ยนขนาดหน้าต่าง ส่งออก/เปิด JSON และตรวจพิกัดตรงเดิม
5. ตรวจเมื่อ Wi-Fi ปิด, ไม่เชื่อมต่อ, ไม่มีสิทธิ์, ไม่มี DNS, gateway ไม่ตอบ ICMP และมี VPN
